# Expedited direct post-deployment adversarial assurance SOP

1. Normalize one trailing slash and require `target_url` to equal the configured HTTPS origin exactly. Reject IP literals, CIDRs, alternate hostnames or ports, userinfo, paths, query strings, fragments, and cross-host redirects. `aws_region` is also required. Repository, commit, image digest, Coolify deployment UUID, `demo_run_id`, evidence run ID, and report location are optional context.
2. Do not require or search for a GitHub workflow workspace or scanner artifacts. When `demo_run_id` is absent, use the Aiden execution ID as the assessment marker.
3. Read AWS posture directly: ALB listeners and HTTP-to-HTTPS redirect, WAF association and required-header rule, certificate/TLS policy, security-group ingress and egress, and EC2 public management exposure. Do not make AWS changes.
4. From the attached remote runner, run exactly one bounded TCP connect scan against the allowlisted hostname: `nmap -Pn -sT -p 1-1024,3000,8000,8080,8443 --host-timeout 3m --max-retries 2 <hostname>`. Do not scan resolved neighboring addresses or another target.
5. Run only GET, HEAD, and OPTIONS probes with `curl` and certificate/TLS inspection with `openssl`. Check HTTP-to-HTTPS enforcement, certificate validity, response security headers, missing and malformed required-WAF-header behavior, and rejection of missing/malformed/expired/wrong-audience authentication. Do not retrieve secrets or create a valid privileged credential.
6. Limit all active testing together to ten minutes and at most 100 HTTP requests. Never perform denial of service, credential stuffing, persistence, destructive or state-changing methods, lateral movement, cloud writes, remediation, secret retrieval, or broad discovery.
7. Evaluate each directly tested control as PASS, FAIL, or NOT ASSESSED. Record VictoriaMetrics, Loki, Jaeger, Grafana, and OpsVerse as `NOT ASSESSED (waived for expedited direct test)`. Their absence must never block the assessment or determine its overall result. Mark a positive WAF or authenticated-flow control NOT ASSESSED when the necessary non-secret test fixture is unavailable; do not infer a pass.
8. Publish exactly one redacted SOC 2-oriented assessment with the marker, exact target, timestamp, AWS posture, open ports, HTTPS/TLS, WAF, authentication and security-header results, significant findings, sanitized evidence commands, limitations, optional deployment identifiers, and the statement that the demo does not claim source-to-artifact provenance.
9. Only after step 8 succeeds, create one Linear issue titled `[SOC 2][PASS|FAIL] Talkdesk secure delivery — <assessment_marker>`. Use the configured default team; if none exists, require exactly one accessible team and stop on ambiguity. Search for the exact marker and reuse one issue on retry. Include direct-test findings, limitations, optional identifiers that were supplied, and redacted report links. Never create more than one issue per assessment marker or any other Linear object.
